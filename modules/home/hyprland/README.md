# Hyprland Lua configuration

Lua-based Hyprland configuration (Hyprland 0.55+), deployed as
out-of-store symlinks into `~/.config/hypr/` by `default.nix`.

## Layout

```
hyprland.lua            Entry point: requires, Notify setup, machine hook, render quirks
workspaces.lua          Static workspace rules (special workspaces)
exec.lua                Autostart / shutdown
appearance.lua          Visual config (borders, gaps, rounding, ...)
animations.lua          Animation config
binds.lua               Key bindings
env.lua                 Environment variables
gpu.lua                 GPU-related config
layouts.lua             Tiling layout config
misc.lua                Misc options
permissions.lua         Permission rules
windowrules.lua         Window rules
shared.lua              Shared constants (mainMod, terminal, ...)

events/                 Event operations: startup, monitorChange, powerChange, brightnessRefresh
systems/                Behavioural subsystems (display, powerManagement)
helpers/                Reusable functions (monitors, workspaces, brightness, sun, power, system, notify)
machine_specific/       Per-host overrides and policy table
diagnostics/            Flat registry of debug options for hyprland.lua
```

`host.lua` and `devices.lua` are **generated by Nix** from
`hosts/<host>/variables.nix` (hostname, sun coordinates, keyboard
layout assignments). They are store paths, not repo symlinks: edit
`variables.nix` and switch to change them.

### Execution model

- Top-level code in every module runs on each config load **and reload**.
  Keep it declarative (`hl.config`, `hl.monitor`, rules, `hl.on`).
- Behaviour on events lives in `events/init.lua`, which orchestrates
  `systems/` and `helpers/` operations. Event handlers run inside
  `Notify.scope()`, which captures errors (log + one notification).
- Subprocesses (`io.popen`) block the compositor's config thread. Keep
  them short; network calls are cached/backed off (see `helpers/sun.lua`).

## Machine policy

`machine_specific/init.lua` selects a per-host module by hostname.
Policies live in `machine_specific/<host>/init.lua`:

| Policy | Meaning |
|---|---|
| `dynamic_monitors` | Recompute monitor modes/positions on events (generic machines) |
| `automatic_brightness` | Adjust brightness on events and on a 30-minute timer |
| `primary_desc` | Description prefix of the monitor that gets workspaces 1-5 (nil = first non-eDP-1) |

Node is expected to have two monitors and uses **static** `desc:`-based
`hl.monitor` rules (no dynamic mode heuristics). An empty-output
fallback rule covers unexpected monitor states.

Workspace assignment lives in one place (`helpers/workspaces.lua`) and
runs for all machines on startup and monitor change. The
`$mainMod+number` focus binds are registered there too (`bind_focus`):
with two or more monitors, keys 1-5 also switch the secondary monitor
to the paired workspace (N+5), so both change together.

## Diagnostics

### Knobs

In `hyprland.lua`:

```lua
Notify.configure({
  debug = { Diagnostics.display_update_brightness },  -- any number of options
})
```

`diagnostics/init.lua` is the single registry of debug options; keys
range from whole events (`monitorChange`) to individual helpers
(`brightness.apply`). Debug is enabled if any enabled function is on
the active call stack, so enabling an event covers everything it calls.

### Sinks

| Channel | Where | When |
|---|---|---|
| DEBUG | `~/.local/state/hypr/alexos.log` | only when enabled via `debug` |
| INFO | log + notification | always (meaningful conditions, e.g. "no valid mode found") |
| ERROR | log (with traceback) + short "see alexos.log" notification | always, from `Notify.scope` |

The log is the diagnostic channel; notifications are for things a user
should act on. Follow the log with:

```sh
tail -f ~/.local/state/hypr/alexos.log
```

### Adding a new diagnostic unit

1. In the owning module: `Notify.register({ ["unit.name"] = M.fn })`.
2. Add a unique key to `diagnostics/init.lua`.
3. (Nothing else — `debug()` finds it via the call stack.)

## API notes

- Monitor rule fields (`mode`, `cm`, `supports_hdr`, `sdrbrightness`,
  `sdr_min_luminance`, `desc:` output matching, empty-output fallback)
  follow https://wiki.hypr.land/configuring/core/monitors/.
- Event names (`monitor.added`, `monitor.removed`, `config.reloaded`,
  `hyprland.start`, `hyprland.shutdown`, ...) per
  https://wiki.hypr.land/configuring/core/advanced-configuration/events/.
- Not documented upstream (verify at runtime when changing):
  exact `HL.Monitor` fields from `hl.get_monitors()` and its ordering;
  whether `hl.monitor` resets omitted fields to defaults (we always
  pass explicit modes); `hl.exec_cmd` failure reporting.
